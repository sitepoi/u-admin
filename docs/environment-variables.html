Environment variables, explained

Every variable the Admin app reads, where to get its value, what happens when it is wrong, and which values must be identical or deliberately different across the Admin app, the Secret API, the CMS and Vercel.

Four values must never exist in this application: SECRETS_ENC_KEY, SECRETS_FINGERPRINT_KEY, SECRET_API_CMS_ENROLL_TOKEN, SECRET_API_RUNTIME_FETCH_TOKEN.

They belong to the Secret API vault, the CMS enrollment flow and the tenant runtime. A source-scan test fails if any of these names appears in this repository.

The 30-second version. Only five values are shared with another system: the Secret API admin token, the Admin Firebase project id (trusted by the Secret API), the CMS system key, Vercel's CRON_SECRET, and the public host. Everything else is Admin-only or must never appear here.

1. How to read this document

Each variable is classified by exposure and by whether it is required. The same key can have different values in Local, Preview and Production; the relationships in section 7 must hold inside each environment.

Required the app cannot serve its main flows without it Optional has a default or only affects one feature Public safe to ship to the browser Secret server-only, never in NEXT_PUBLIC_ Same must match another system Different must not be reused Never here must not exist in this app

Three environments, one key set

Environment Where values live Notes
Local .env.local (gitignored) Loaded by next dev. Restart after edits. The demo command sets its own values.
Vercel Production Project -> Settings -> Environment Variables Server values are read at runtime. NEXT_PUBLIC_* is inlined at build time.
Vercel Preview Same UI, Preview scope Preview URLs are different hosts; the host guard rejects them unless you configure a fixed preview host.

Build-time versus runtime. Any variable starting with NEXT_PUBLIC_ is baked into the JavaScript bundle. Changing it in Vercel does nothing until you create a new deployment. Server variables are read when a request runs, but a redeploy is still the reliable way to apply a full set of changes.

2. The system map

The Admin app is one of four systems. The arrows show who holds which credential, and why several similar-looking values must stay separate.

Browser -> Admin app -> Admin Firebase project | Secret API -> Vault (ciphertext + master key) | CMS system API | Tenant projects (read-only) | CMS -> Secret API (enrollment token) | Tenant runtime -> Secret API (runtime-fetch token)
  • The browser talks to Firebase Auth directly and to the Admin app. It never calls the Secret API.
  • The Admin app talks to the Secret API server-to-server with a service token, and forwards the operator's fresh Firebase ID token as actorIdToken.
  • The Secret API verifies that actor token itself, so it must trust the Admin Firebase project.
  • The Admin app reads aggregates from tenant projects with a dedicated read-only account.
  • The vault keys never leave the Secret API.

6. Detailed reference

6.1 Host and access

PLATFORM_HOST Required Server Must equal public host
What it is
The single DNS host the application serves. Middleware compares the request Host header to this value and returns a bare 404 for everything else, including the *.vercel.app URL, preview URLs and every tenant host.
Where to get it
Vercel -> Settings -> Domains for the domain you attached. For a first smoke test, use the production Vercel host, for example u-admin.vercel.app.
Format
admin.uniconhub.com. Bare host, no scheme, no path. A port is only for local development.
Must match
The exact URL operators open. A mismatch is the most common cause of "Not Found" on Vercel.
If wrong
Every route returns 404. Runtime logs contain a warning when it is empty.
Security note
This is defense in depth, not a secret. Certificate transparency exposes hostnames.
PLATFORM_ALLOWED_DEV_HOSTS Optional Server Local only
What it is
Extra hosts accepted only when NODE_ENV is not production.
Where to get it
You choose. Use localhost:3000,127.0.0.1:3000 for local development.
Format
Comma separated host:port entries. Schemes are stripped if pasted.
Rule
Ignored in production. Never rely on it to make a Vercel URL work.
If wrong
Local requests return 404. Add the exact host:port and restart.
PLATFORM_SESSION_TTL_HOURS Optional Server
What it is
Lifetime of the __Host-platform_session cookie. Default 8, clamped to 1-24.
Where to get it
Your security policy. There is no external source.
Tradeoff
Shorter limits exposure on a lost laptop; longer reduces re-authentication. Reveal always requires a fresh actor token, independent of this value.
Must match
Nothing outside this app. It must not exceed the Firebase session cookie maximum, which the clamp already prevents.
PLATFORM_REVEAL_FRESH_AUTH_SECONDS Optional Server Keep at or below Secret API
What it is
Maximum age of the actor token's auth_time that the Admin app accepts for a reveal. Default 300, clamped to 30-900.
Where to get it
Your security policy, aligned with the Secret API owner.
Cross-project rule
The Secret API independently checks freshness. Set the Admin value lower than or equal to the Secret API window. If the Admin app is looser, reveal fails at the Secret API with a re-authentication error after the operator has already done the work.
If wrong
Operators are asked to re-authenticate too often, or a valid session is rejected upstream.
PLATFORM_ADMIN_EMAILS Required Server Members of Admin Firebase Auth
What it is
An exact email allowlist checked in addition to Firebase Authentication. A valid Firebase user who is not listed cannot create or keep a session.
Where to get it
Firebase Authentication -> Users, in the Admin project. Use the emails of current operators.
Format
Comma separated, case-insensitive, exact addresses. No wildcards, no domain matching.
Must match
The Firebase user emails. If you change an email in Firebase, update this list as well.
If wrong
Sign-in returns 401 UNAUTHORIZED with "not authorised for the platform".
Security note
Not a secret, but it is operator PII. It is never sent to the browser; the settings page only shows a count.
PLATFORM_IP_ALLOWLIST Optional Server
What it is
An extra network gate in middleware. Empty disables it.
Where to get it
The egress ranges of your office, VPN or access proxy. For Cloudflare Access, the app sees the real client IP in cf-connecting-ip, so list operator egress ranges, not Cloudflare ranges.
Format
Comma separated exact IPv4, IPv4 CIDR, or exact IPv6. IPv6 CIDR is not supported.
Warning
The check trusts proxy forwarding headers. Only enable it behind a proxy that strips or overwrites client-supplied x-forwarded-for.
If wrong
A bare 404 for every request, indistinguishable from a host mismatch.

6.2 Public Firebase

NEXT_PUBLIC_FIREBASE_API_KEY Required Public
What it is
The Firebase Web API key used by the browser SDK for email/password sign-in and MFA.
Where to get it
Firebase console -> Project settings -> General -> Your apps -> Web app -> SDK setup and configuration -> Config.
Format
Starts with AIza.
Is it a secret?
No. It identifies the project and is visible in every browser. Protection comes from Firebase quotas, optional App Check, the email allowlist, MFA and Firestore rules.
Must match
The same Admin project as the other three public values.
Build-time
Inlined into the bundle. A change requires a new deployment.
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN Required Public
What it is
The domain used by Firebase Auth, and by the app's CSP for Auth requests and MFA or reCAPTCHA frames.
Where to get it
Same Firebase web app config block.
Format
YOUR_PROJECT_ID.firebaseapp.com, unless you configured a custom auth domain.
If wrong
The browser cannot complete sign-in, and the CSP blocks the Auth iframe.
NEXT_PUBLIC_FIREBASE_PROJECT_ID Required Public Equals PLATFORM_FIREBASE_PROJECT_ID
What it is
The Admin project id used by the browser SDK.
Where to get it
Same Firebase web app config block, or the project settings header.
Must match
PLATFORM_FIREBASE_PROJECT_ID. If they differ, the browser signs users into one project and the server verifies tokens against another.
Must differ
The Secret API vault project and every tenant project.
NEXT_PUBLIC_FIREBASE_APP_ID Required Public
What it is
The Firebase Web app id.
Where to get it
Same Firebase web app config block.
Format
1:PROJECT_NUMBER:web:SHORT_ID.
Note
Do not confuse it with the project id or project number.

6.3 Firebase Admin

PLATFORM_FIREBASE_PROJECT_ID Required Server Trusted by Secret API Different from vault project
What it is
The Admin Firebase project. Its Auth issues the ID tokens the app verifies, and its Firestore stores the platform_tenants, platform_audit_log, platform_report_snapshots and platform_settings collections.
Where to get it
The project_id field inside the Admin service account JSON, or the Firebase project settings.
Must match
NEXT_PUBLIC_FIREBASE_PROJECT_ID, and the project id the Secret API is configured to trust when it verifies actorIdToken.
Must differ
The Secret API vault project, the CMS projects and every tenant project. This separation is the blast-radius boundary.
PLATFORM_FIREBASE_CLIENT_EMAIL Required Server Same JSON as the private key
What it is
The service account identity used by Firebase Admin.
Where to get it
The client_email field of the Admin service account JSON.
Must match
The private key: both must come from the same generated key file.
Must differ
The reporting service account. Never reuse one account for both roles.
PLATFORM_FIREBASE_PRIVATE_KEY Required Secret Same JSON as the client email
What it is
The private key that signs Admin SDK calls for Firestore, Auth and session cookie creation.
Where to get it
Firebase console -> Project settings -> Service accounts -> Generate new private key. Copy the private_key field.
Format
Quoted, with escaped newlines: "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n". The value must contain BEGIN PRIVATE KEY.
Security
Full control of the Admin project. Never put it in NEXT_PUBLIC_, never log it, never commit it. The app never sends it anywhere.
Rotation
Create a new key in GCP, update Vercel, deploy, then delete the old key.

6.4 Secret API client

SECRET_API_BASE_URL Required Server Same environment as the token
What it is
The base URL the Admin server calls for secret metadata, reveal, delivery, retirement and secret health.
Where to get it
The Secret API deployment URL, from the team that operates it.
Format
https://secret-api.uniconhub.com. No trailing slash is required; it is stripped. HTTPS is enforced in production.
Must match
The same environment as SECRET_API_ADMIN_SERVICE_TOKEN. A production token against staging, or the reverse, is a common and confusing failure.
Never
Never used in browser code. The browser never calls the Secret API.
SECRET_API_ADMIN_SERVICE_TOKEN Required Secret Identical in Secret API
What it is
The bearer token the Admin server presents to Secret API admin endpoints.
Where to get it
Generated by the Secret API operator and stored in both systems. If you operate both, generate a random value and configure it on both sides in the same change window.
Must match
The Secret API's expected admin token. This is the most important cross-project equality in the system.
Security
Grants access to admin endpoints, still subject to the actor token checks the Secret API performs. Never public, never logged, never written to audit metadata.
If wrong
The Secret API returns 401 or 403, and the Admin app surfaces 503 SECRET_API_UNAVAILABLE.
Rotation
Update both systems close together; reveal and delivery fail between the two updates.
SECRET_API_TIMEOUT_MS Optional Server
What it is
Per-request timeout for the Secret API. Default 5000, clamped 500-30000.
Where to get it
You choose, based on the Secret API's measured latency.
Tradeoff
Too low causes false 503s during cold starts; too high makes failure pages slow.
Must match
Nothing. It is local to this client.

6.5 CMS

These are platform values, not tenant values. CMS_SYSTEM_API_BASE_URL is the CMS host that serves /api/system/.... CMS_SYSTEM_API_KEY is the platform system key configured in the CMS. The tenant is supplied at runtime when an operator provisions a tenant:

/api/system/KEY/ctgc/TENANT_ID/CMS_PROJECT_ID

Never put a tenant id, a tenant host or a per-tenant key in either variable.

CMS_SYSTEM_API_BASE_URL Required Server Same environment as the CMS key
What it is
Base URL for the CMS system endpoints that create tenants and retry first-party enrollment.
Where to get it
The CMS deployment URL, from the CMS team.
Format
https://cms.uniconhub.com, no trailing slash required.
Not tenant-specific
One value for the whole platform. A call looks like https://cms.uniconhub.com/api/system/KEY/ctgc/TENANT_ID/CMS_PROJECT_ID. The tenant id and CMS project id are path parameters, not part of this URL. Do not paste a tenant host here.
Must match
The same CMS environment as CMS_SYSTEM_API_KEY.
CMS_SYSTEM_API_KEY Required Secret Identical in CMS Different from enrollment token
What it is
The key embedded in the CMS system path: /api/system/KEY/ctgc/TENANT_ID/CMS_PROJECT_ID. It authorizes tenant creation and enrollment retry.
Where to get it
The CMS team generates the system API key; the CMS stores the same value.
Not tenant-specific
One platform-level system key, shared with the CMS. It is not a per-tenant key and it is not a tenant id. The same key is used for every tenant because the tenant is identified in the request path.
Must match
The CMS's configured system key.
Must differ
SECRET_API_CMS_ENROLL_TOKEN. That token authenticates the CMS calling the Secret API. This key authenticates the Admin app calling the CMS. Different directions, different secrets.
Security
Can create tenants. It travels in the URL path, so the client never logs the URL; log lines replace the key with [cms-api-key].
If wrong
Provisioning fails and the tenant is marked failed with a sanitized error.
CMS_SYSTEM_API_TIMEOUT_MS Optional Server
What it is
Provisioning request timeout. Default 10000, clamped 1000-60000.
Where to get it
You choose. CMS tenant creation can be slow on the first call.
If too low
The attempt is recorded as failed even though the CMS may still be creating the tenant. Retry uses the enrollment endpoint on conflict, so recovery is possible.
PLATFORM_CMS_HOST_SUFFIX Optional Server Must exist in DNS
What it is
Suffix used to generate a default CMS host as TENANT_ID.SUFFIX when a tenant record omits cmsHost. Default cms.uniconhub.com.
Where to get it
The wildcard DNS zone and TLS certificate that the CMS actually serves.
Must match
Real DNS. A generated host that does not resolve is a broken tenant.
Note
Not used when the tenant record provides an explicit host.
PLATFORM_PUBLICWEBSITE_HOST_SUFFIX Optional Server Must exist in DNS
What it is
Same as above, for the tenant public website host. Default publicwebsite.uniconhub.com.
Where to get it
The wildcard DNS zone and TLS certificate used by the public website deployment.
Must match
Real DNS and the Vercel project or hosting that serves the tenant sites.

6.6 Reporting

PLATFORM_REPORTING_SERVICE_ACCOUNT_JSON Conditional Secret Different from Admin service account
What it is
A dedicated read-only Google Cloud service account used to read aggregates from every tenant project. Required only for reporting refresh and the cron job.
Where to get it
Google Cloud console -> IAM & Admin -> Service accounts -> create platform-reporting-reader -> grant roles/datastore.viewer on each tenant project -> Keys -> Add key -> JSON.
Format
One-line JSON. In .env.local, wrap it in single quotes so the escaped newlines inside the private key stay valid JSON.
Must differ
The Admin service account and every Secret API credential. Read-only, tenant projects only.
If missing
Reporting refresh returns a configuration error. The rest of the app still works.
Security
The code stores counts only, but the IAM role can read tenant documents. Guard the key and rotate it like any other credential.
PLATFORM_REPORTING_MAX_CONCURRENCY Optional Server
What it is
Number of tenant projects collected in parallel. Default 3, clamped 1-10.
Where to get it
You choose, based on Firestore quotas and observed latency.
Tradeoff
Higher finishes faster but can trigger quota errors, which are recorded as partial failures.
PLATFORM_REPORTING_TENANT_TIMEOUT_MS Optional Server
What it is
Maximum time spent on one tenant before it is recorded as a partial failure. Default 10000, clamped 1000-60000.
Where to get it
You choose. Keep it below the platform function timeout.
PLATFORM_REPORTING_CRON_SECRET Optional Secret Identical to Vercel CRON_SECRET
What it is
Shared secret that allows the reporting refresh route to run without a session, for Vercel Cron.
Where to get it
Generate a random value, for example openssl rand -base64 32, and set it in both places.
Must match
Vercel's CRON_SECRET. Vercel sends Authorization: Bearer CRON_SECRET; the app compares it in constant time.
If missing
Only manual refresh works. Cron requests are rejected.
Security
Can trigger a reporting refresh. It cannot reveal or modify secrets.
PLATFORM_REPORTING_OBJECT_COLLECTION and seven related mapping keys Optional Server Must match tenant Firestore schema
What they are
The collection and field names the reporting collector reads in each tenant project. Defaults: objects / objectTypeId, api_requests / apiVersion, first_party_requests / isError, users (lastActiveAt is fixed), platform_usage/current (storageBytes is fixed).
Where to get them
The CMS data model, confirmed against a real tenant project in the Firestore console.
Must match
Every tenant project. If one tenant uses different names, that tenant records a partial failure while the rest of the refresh continues.
Not shared
Nothing in the Secret API uses these names.

6.8 Vercel platform

CRON_SECRET (Vercel) Conditional Secret Equals PLATFORM_REPORTING_CRON_SECRET
What it is
A Vercel variable used by Vercel Cron. Vercel sends it as Authorization: Bearer CRON_SECRET when it invokes the cron path. The app does not read this name directly.

7. Cross-project comparison

This is the part that causes most production incidents: values that must be equal, values that must be different, and values that must not exist here at all. The exact variable names in the Secret API and CMS projects depend on those repositories; the contract below is what matters.

7.1 Values that must be identical

Copy the value from one system to the other; do not "recreate" it independently.
Admin app value Counterpart Why
PLATFORM_FIREBASE_PROJECT_ID The Secret API's trusted Admin project id (its own variable name) The Secret API verifies the forwarded actorIdToken. It must check the token issuer and audience against the Admin Firebase project. If it checks its own vault project id instead, every reveal fails with 401/403.
NEXT_PUBLIC_FIREBASE_PROJECT_ID PLATFORM_FIREBASE_PROJECT_ID The browser signs users into the project whose tokens the server verifies.
SECRET_API_ADMIN_SERVICE_TOKEN The Secret API's expected admin service token The bearer token must match on both sides. This is the primary shared secret.
CMS_SYSTEM_API_KEY The CMS's configured system API key The key is part of the provisioning URL path.
PLATFORM_REPORTING_CRON_SECRET Vercel CRON_SECRET Vercel sends it as a bearer token; the app compares it in constant time.
PLATFORM_HOST The domain attached in Vercel / DNS The host guard accepts exactly this host.
PLATFORM_FIREBASE_CLIENT_EMAIL PLATFORM_FIREBASE_PRIVATE_KEY Both must come from the same service account JSON. A mismatched pair fails to authenticate.
PLATFORM_ADMIN_EMAILS Firebase Authentication users in the Admin project Membership, not literal equality: every operator must be in both.
PLATFORM_REVEAL_FRESH_AUTH_SECONDS The Secret API's freshness window Admin should be lower than or equal to the Secret API. If Admin is looser, the upstream rejects a reveal the operator already re-authenticated for.

7.2 Values that must be different

Reusing these collapses a security boundary. Keep them separate even in staging.
Value A Value B Why they must differ
Admin Firebase project (PLATFORM_FIREBASE_*) Secret API vault Firebase project The Admin app must not be able to reach the vault database, and the vault must not be able to read platform data. Separate projects enforce this at IAM level.
Admin service account Reporting service account Least privilege. Reporting is read-only on tenant projects; the Admin account is not.
Admin service account Secret API service account Different projects and different blast radius. Never share a key file.
CMS_SYSTEM_API_KEY SECRET_API_CMS_ENROLL_TOKEN Different directions: one authenticates the Admin app to the CMS, the other authenticates the CMS to the Secret API. The Admin app must never be able to enroll keys.
SECRET_API_ADMIN_SERVICE_TOKEN SECRET_API_RUNTIME_FETCH_TOKEN Different consumers: the Admin server versus tenant runtimes. A runtime token must never grant admin access.
SECRET_API_CMS_ENROLL_TOKEN SECRET_API_RUNTIME_FETCH_TOKEN Enrollment and runtime delivery are separate trust paths.
Local demo secrets (PLATFORM_E2E_*) Any production value E2E mode must never be available in a production deployment.
Admin Firebase web app config Any tenant Firebase web app config Tenants use their own projects. Reusing one would mix auth domains and data.

7.3 Values that must never appear in this app

These belong to the vault or to other consumers. A source-scan test enforces this list.
Variable Where it belongs What it does there
SECRETS_ENC_KEY Secret API only Symmetric master key that encrypts private keys at rest. Leaking it compromises every key. The Admin app is intentionally unable to use it.
SECRETS_FINGERPRINT_KEY Secret API only HMAC key for deterministic fingerprints and key ids. Leaking it allows correlation and forgery, but not decryption.
SECRET_API_CMS_ENROLL_TOKEN Secret API and CMS Authenticates CMS auto-enrollment calls. Provisioning triggers the CMS endpoint; the Admin app never holds the token.
SECRET_API_RUNTIME_FETCH_TOKEN Secret API and tenant runtime Authenticates runtime-fetch delivery. Tenant runtimes hold it; the Admin app does not.

7.4 What the Secret API needs from this project

The Secret API needs the Admin project id to verify actorIdToken. It does not need the Admin service account key. A Firebase project id is an identifier; verification uses Google's public signing keys.

  1. The Admin browser signs in to the Admin project and obtains an ID token with MFA.
  2. The Admin server forwards that token as actorIdToken with the service token.
  3. The Secret API verifies the signature, the issuer and audience for the Admin project, the MFA claim, the owner role and auth_time freshness.
  4. Only then does it decrypt and return the key, or perform delivery or retirement.

7.5 Environment mismatch traps

  • Production Admin pointing at a staging Secret API: service token rejected, tenant ids unknown.
  • Production Admin pointing at a staging CMS: provisioning creates tenants in the wrong place.
  • Rotating the Secret API admin token on one side only: every secret action returns 503.
  • Using the Secret API vault project id in PLATFORM_FIREBASE_*: sessions verify against the wrong project and every platform page fails.
  • Using SECRET_API_CMS_ENROLL_TOKEN as CMS_SYSTEM_API_KEY: provisioning is rejected by the CMS.
  • Reusing the reporting service account as the Admin service account: the reporting account loses its least-privilege boundary.

9. Formats and gotchas

Private keys and newlines

In .env.local, wrap the key in double quotes and keep the escaped \n sequences: 

PLATFORM_FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEv...\n-----END PRIVATE KEY-----\n"

The app converts escaped newlines to real newlines. The value must contain BEGIN PRIVATE KEY. A key pasted with real line breaks inside a quoted value also works, but is easier to break when copying.

Service account JSON

Use single quotes around the whole JSON so the escaped newlines inside private_key remain valid JSON: 

PLATFORM_REPORTING_SERVICE_ACCOUNT_JSON='{"type":"service_account","project_id":"...","client_email":"...","private_key":"-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"}'

In Vercel's UI, paste the same one-line JSON without surrounding quotes; the UI stores the literal value.

Hosts

  • Use a bare host: admin.uniconhub.com.
  • Do not add https:// or a path. The current code tolerates them, but clean values avoid surprises.
  • A trailing dot and mixed case are normalized.
  • www. is a different host from the apex domain.

Lists and ranges

  • PLATFORM_ADMIN_EMAILS: comma separated, exact, case-insensitive. No wildcards or domain rules.
  • PLATFORM_IP_ALLOWLIST: exact IPv4, IPv4 CIDR, exact IPv6. IPv6 CIDR is not supported.
  • PLATFORM_ALLOWED_DEV_HOSTS: comma separated host:port.

URLs

  • Trailing slashes on SECRET_API_BASE_URL and CMS_SYSTEM_API_BASE_URL are stripped.
  • SECRET_API_BASE_URL must be HTTPS in production; the configuration loader rejects plain HTTP.
  • The CMS URL is not protocol-checked, but use HTTPS.

Build-time values

NEXT_PUBLIC_* is embedded in the client bundle. Changing it in Vercel without a new deployment has no effect. This is the most common "I changed it but nothing happened" cause.

13. FAQ

Is the Firebase Web API key a secret?

No. It is public by design and appears in every browser. Security comes from Firestore rules, the email allowlist, MFA and Firebase quotas.

Can the Admin app and the Secret API share one Firebase project?

No. They are separate by design so that a compromise of one does not expose the other. The Secret API only needs the Admin project id to verify actor tokens, not its credentials.

Does the Admin app need the encryption key to reveal a secret?

No, and it must never have it. Reveal is delegated to the Secret API with a fresh actor token. If the Secret API is unavailable, the Admin app returns 503 and does not fall back to local decryption.

Why are there two service accounts (Admin and reporting)?

Least privilege. The reporting account is read-only on tenant projects. The Admin account has full access to the Admin project and none to the vault or tenant projects.

Can CMS_SYSTEM_API_KEY equal SECRET_API_CMS_ENROLL_TOKEN?

No. They authenticate opposite directions: Admin to CMS, and CMS to Secret API. The Admin app must never be able to enroll keys.

Why does the Secret API need PLATFORM_FIREBASE_PROJECT_ID?

It must check that the forwarded actor token was issued for the Admin project. It only needs the project id, which is public, plus Google's public signing keys. It never needs the Admin service account key.

What happens if the Secret API is down?

Secret metadata pages show an unavailable message, and reveal, deliver and retire return 503 SECRET_API_UNAVAILABLE. Nothing is decrypted or cached locally.

Do I need to restart after editing .env.local?

Yes. Next.js reads environment files at startup.

Do I need to redeploy after changing Vercel variables?

Yes. Server values can be read at runtime, but NEXT_PUBLIC_* is baked into the build. Redeploying with a cleared build cache is the reliable path.
